# 3GPP RAG Chatbot

An evidence-grounded Retrieval-Augmented Generation (RAG) chatbot for Telecom 3GPP Release 17 standards documentation.

The system is designed around a strict principle:

> **The chatbot should answer only when the supplied 3GPP evidence supports the answer. Otherwise, it refuses.**

## Overview

This project implements a production-oriented RAG pipeline for complex 3GPP standards PDFs.

The initial knowledge base contains:

* **3GPP TS 23.501 V17.6.0 (2022-09)** — 5G System Architecture
* **3GPP TS 23.502 V17.6.0 (2022-09)** — 5G System Procedures
* **3GPP TS 23.503 V17.6.0 (2022-09)** — Policy and Charging Control
* **3GPP TS 33.501 V17.6.0 (2022-06)** — Security Architecture

The chatbot uses structure-aware document parsing, hybrid retrieval, reranking, evidence gating, Groq generation, citation validation, and claim-level verification.

## Anti-Hallucination Design

This project does not rely only on a prompt such as "do not hallucinate".

It uses multiple independent controls:

### 1. Restricted Knowledge Source

The application is limited to the indexed 3GPP documents.

Questions outside the corpus should be refused.

### 2. Evidence Sufficiency Gate

Retrieved passages are evaluated before Groq generation.

Weak retrieval can result in:

```text
I could not find sufficient supporting information in the provided 3GPP documents.
```

### 3. Citation Validation

The LLM is not trusted to invent document metadata.

Citations reference retrieved chunk IDs, and the application resolves those IDs back to trusted retrieval metadata.

### 4. Claim-Level Verification

Generated factual claims are extracted and checked against the retrieved evidence.

If any claim is unsupported, the final response is rejected.

### 5. Deterministic Metadata

Specification, version, section, page and chunk metadata come from the retrieval layer rather than being generated by the LLM.

## Safety / Hallucination Policy

The system should not claim that an answer is correct merely because an LLM generated it.

The production acceptance rule is:

```text
Retrieved evidence
        |
        v
Evidence gate
        |
        v
Grounded generation
        |
        v
Citation validation
        |
        v
Claim-level verification
        |
        +---- unsupported claim ----> REFUSE
        |
        v
Final answer
```

The target is:

```text
0 unsupported claims returned
```

on the validated evaluation benchmark.

This is an engineering acceptance criterion rather than a universal mathematical guarantee about language models.

## Why the LLM Is Not the Source of Truth

The source of truth is the retrieved 3GPP evidence.

The LLM is responsible for:

* interpreting the user's question
* summarizing supplied evidence
* producing a readable answer

The LLM is not allowed to expand the knowledge base with outside information.

## Current Limitations

* Retrieval and verification thresholds require calibration against a larger manually validated benchmark.
* PDF parsing quality can vary for unusually complex layouts.
* CPU-based reranking can be slow on low-memory machines.
* The initial corpus is limited to four 3GPP specifications.
* Source PDFs are not included in the repository.
